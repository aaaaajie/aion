# AION 三组成对评测方法

本文件交付方法，不报告性能提升。旧中断日志只保留作历史归档，不能作为新旧比较样本。

## 共同约束

将旧基线 A 与本次实现 B 固定成独立代码快照，记录压缩包 SHA-256、依赖/工具链版本、配置摘要和平台题目版本。旧基线使用自己的数据库契约，新实现使用版本 16；不互相恢复数据库。基线快照路径见 [交付清单](AION_交付验收.md)。

每对使用完全相同的题目、Flag 集合、模型版本、推理设置、角色映射预算、比赛窗口、容器容量、CPU/内存/磁盘限制、网络条件和提示策略。两次均从干净靶机、空状态库、空 Agent 记忆和独立工作目录开始；禁止读取对方产生的证据、缓存或答案。模型服务的缓存条件应一致；服务无法重置缓存时，记录限制并交替运行顺序。

至少准备 6 对独立重复，按 A→B、B→A 交替；同一对固定随机种子和场景版本。顺序提前登记，不因结果调整或删除失败样本。基础设施中断也记录原始结果；如确需重跑，保留失败样本，按预先登记的规则给两组同样重跑机会。

整场窗口从实际 Run 开始时间计算，包含排队、模型退避、工具执行、提交核对、等待和恢复。时限到达后停止计分，但仍单独记录必要清理的耗时与调用开销。

## 第一组：直接执行与多答案题

选择无需委派也可完成的固定小题集，包括文件/响应中的精确答案、需要保持会话的操作链、多答案题，以及提交接受后平台延迟标记完成的题目。

每对使用相同题序与平台状态转移。新实现允许零 Worker，旧实现保持其原调度逻辑。比较总得分、完整解题数、首题/全场耗时和全部 token；同时检查部分答案不会提前终止、重复提交与结果不确定不会导致盲目重试。

## 第二组：独立并行与连续依赖

固定若干包含两项独立取证任务和一条至少三个依赖步骤的题目。独立任务允许同时执行；依赖步骤要求复用原会话，例如建立连接、获得对象 ID、使用该 ID 验证结果。加入只读复核需求与一项明确取消的支线。

两组使用同一资源容量和窗口，不人为限制新实现每题 Worker 数。记录任务创建数、排队延迟、重复任务键、会话重建数、报告次数、取消后的迟到结果，以及关键链路总耗时。辅助指标解释得分和成本差异，不替代总得分作为首要指标。

## 第三组：长窗口、暂停和故障恢复

固定混合题目集与较长整场窗口，在事先登记的时刻执行相同故障脚本：可恢复模型错误、Chief 暂停并释放靶机、暂停保留靶机、Runtime 进程退出和平台关闭短暂失败。故障时刻按 Run 相对时间设定，不根据某组进展临时选择。对当时无活动任务的故障记为“未触发”，仍保留整对。

验证恢复后的总得分、解题数、终态时间、资源残留和清理失败。新实现未完成 Worker 应中断，由原 Solver 决定是否用新键重做；旧实现按自身机制执行。报告重放、重复提交和恢复消耗全部计入。

## 计分、消耗与结果表

首要指标为平台在绝对截止时确认的**总得分**；其次依次为完整解题数、耗时和 token。部分答案所得分数保留，完整解题数必须以 `is_completed` 计数。超时、零分、启动失败及中途退出的题目均保留在分母中。

每个物理模型请求都计入：主请求、重试、错误请求、会话摘要、旁路观察、Skill 发现和平台接口适配。按请求 ID 去重，分别记录输入、缓存命中、未缓存输入、输出；缺失 usage 标为未知，同时给出缺失调用数，不能补零或宣称已知的完整成本。旧实现如缺少这种事件，在独立评测夹具的模型 HTTP 边界增加相同计量，并记录夹具哈希，不改变其策略。

每条样本记录以下字段：

| 字段组 | 必填内容 |
|---|---|
| 配对标识 | group、pair_id、A/B、执行顺序、种子、题目清单及哈希 |
| 环境 | 代码快照哈希、模型及推理参数、预算、工具链、平台版本、资源条件 |
| 窗口 | run_id、开始/绝对截止/终态时间、故障计划和实际触发时间 |
| 结果 | 平台总得分、完整解题数、每题得分/正确答案数/完成状态、失败原因 |
| 消耗 | 物理调用数、四类 token、缺失指标数、重试与辅助调用明细、墙钟耗时 |
| 生命周期 | Worker 数、重复执行数、清理失败、确认释放时间、残留资源 |
| 证据 | 原始只读数据库、平台截止快照、调用账本与日志的路径及哈希 |

逐对给出 B−A 的得分、解题数、耗时和各 token 差值，再报告配对差值的均值、中位数和分布。分组保留全部原始对，不只展示成功题或成功运行；对未知成本单独列出覆盖率。只有完成这些新鲜成对运行后，才能得出性能方向结论。

## 本次精简工具与短图谱的消融

在上述三组题目内增加四个独立条件：精简工具关/观察关、精简工具开/观察关、精简工具关/观察开、两者都开。用 `AION_COMPACT_TOOLS`、`AION_SOLVER_OBSERVATION` 设置，保留相同简短提示、Skills 目录、主模型和预算，交替配对顺序，以分别解释工具呈现与旁路观察的影响。再与 `.aion/refactor-baselines/20260905T101822Z/worktree.tar.gz` 的原提示/工具策略做整套比较。每个条件从新 Run 和干净环境开始，不共享图谱或已激活 Skill。

同时记录 `purpose=observation` 的物理调用数/四类 token、有效/失败/取消图谱次数、工具检索次数及检索结果进入主线后的输入消耗。固定 Schema 的字节或估算 token 下降只说明请求结构变短，不能替代完整比赛 token、得分或耗时结果。
