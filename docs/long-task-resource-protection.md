# 长任务资源保护与活动提醒

Linux Shell 命令在执行用户代码前进入独立 cgroup v2；前台和后台使用同一保护路径。Runtime、任务监督进程和既有 VPN 移入 `aion-control`，任务放在同级 `aion-shell-tasks` 池下。委派根节点清空进程后才启用 domain 控制器。服务配置使用 `Delegate=cpu memory pids`；缺少可写委派、控制器或 `cgroup.kill` 时拒绝启动，不退回无保护执行。每个任务和任务池同时有内存、CPU、进程／线程数上限。

运维环境变量（模型工具参数不能修改预算）：

| 环境变量 | 默认值 |
| --- | --- |
| `AION_SHELL_TASK_MEMORY_MIB` | 512 MiB |
| `AION_SHELL_TASK_CPU_CORES` | 1 核 |
| `AION_SHELL_POOL_MEMORY_MIB` | 主机内存的 50%，最高 3072 MiB |
| `AION_SHELL_POOL_CPU_CORES` | 主机核数的 50% |
| `AION_SHELL_TASK_PIDS_MAX` | 512 个进程／线程 |
| `AION_SHELL_POOL_PIDS_MAX` | 2048 个进程／线程 |

任务池和任务均禁用 swap。CPU 超额节流；内核 `memory.events` 的 OOM kill 和 `pids.events` 的进程数上限事件用于判定资源终止原因，随后回收整个任务树并保留已有输出。不会仅根据 SIGKILL 推断 OOM。预算、峰值和原因沿用任务事件，投影到回执、完成通知及只读详情，不新增任务表。macOS 继续开发执行并明确标记未提供 Linux cgroup 进程数硬限制。

Shell 默认启用 `pipefail`，不启用 `set -e`。`timeout … | tail` 的超时不再被最后一级成功退出掩盖；脚本显式覆盖退出码仍按最终状态记录。Runtime 超时、命令非零、资源限制、用户停止分别记录原因。

Solver 的活动提醒来自持久化事件：自创建、最近进展记录或已交付提醒起，同时满足 5 分钟和 12 次新完成执行，才随下一次模型输入加入建议。搜索、分页、轮询和重复交付不计数。提醒不证明实验无效、不锁工具、不强制复盘，也不会单独唤醒等待中的模型。只有成功的模型响应确认提醒交付；`new_information` 记录或平台接受 flag 重置窗口。

提示词增加基于接口、参数、认证状态和响应基线的小范围后台扫描原则，要求复用运行中扫描；登录场景不默认密码爆破。长提取脚本先验证短样本、循环收敛和有限待提交队列；输出使用任务捕获或工作目录文件。Solver 无独立工作时等待，Worker 有界读取后报告。

## 本地验收

定向测试覆盖退出状态、生命周期、通知交付、活动窗口和重试、跨 Run 任务详情及资源信息投影、工具上下文预算。

Linux 专项回归应在可写委派的 cgroup v2 环境中用缩小预算验证进程超限、内存超限、有界的 160 线程任务、并行正常任务存活及任务树清理。macOS 下的 Linux 专用 pytest 会跳过；若 Docker 只读挂载 `/sys/fs/cgroup`，只能完成配置探测，不能把跳过或模拟结果算作 Linux 验证通过。

本阶段不包含云端部署、生产 systemd 启动验证或新挑战运行。后续部署需检查委派并核实上轮容器已释放；相同预算下多轮比较完成率、重复执行量、等待时间和资源峰值。
