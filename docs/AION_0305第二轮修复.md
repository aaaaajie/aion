# 03／05 第二轮修复与验收

本轮修复执行事实、自动复盘、校准依赖、HTTP 重定向回执及观察器输入。没有部署、恢复比赛、调用真实模型或请求比赛目标；保留工作区原有修改。观察器默认关闭，可通过 `AION_SOLVER_OBSERVATION=true` 显式启用进行评估。

## 执行记录与提醒

复用 `shell_task_started`、`shell_task_finished`、`http_interaction_status_changed` 和 `agent_resources_invalidated`，不增加数据库表。Runner 在原有工具结果事件中保存从完整回执提取的 `execution_fact`，记录输出是否完整读取。状态只能来自任务回执和任务管理器，不解析 stdout 中的进程列表或模型推断。

累计六次尚未复盘的执行完成触发提醒；超时、取消、中断和资源代次变化直接触发。同一个后台任务／HTTP interaction 的轮询不重复计数，查询、检索和进度上报不计数。提醒送达沿用成功模型响应后的事件确认；失败响应和重启不会丢失待送达提醒。送达后再增加六次未覆盖完成才重复提醒，不拦截任何工具。

运行中和结果待读取的任务单独进入上下文；任务集合变化时更新，包括清除已经结束且读完输出的任务，防止旧的 running 摘要持续留在记忆中。完整读取是工具可观测的输出读取，不等同于证明模型理解了内容。

自动触发覆盖 Shell、HTTP 请求／批次／Web 探测、网络发现、服务探测和 SSH 执行等已登记执行入口。任意 Shell 内部包含多少子实验不做猜测，一次任务只作为一个完成单位。

## 复盘接口

`solver_progress.review` 增加以下字段，继续通过现有事件日志恢复：

| 字段 | 用途 |
| --- | --- |
| `covered_sequences` | 明确已经复盘的工具结果、任务完成或环境变化事件，不要求其为有效实验 |
| `calibration_status` | `unknown`、`negative_control_only` 或 `verified` |
| `calibration_basis` | 实现正确性的校准依据；声明 verified 时必填 |
| `calibration_sequences` | 引用当前有效且经过校准的既有复盘记录 |
| `environment_dependent` | 默认 true；环境代次变化使此前相关校准需要重新验证 |
| `observation_revision`、`observation_assessment` | 可选、成对提供：图谱版本及 `corrected/dismissed/uncertain` 自报判断 |

有效实验需要校准依据或有效校准引用，只有负对照不能声明实现有效。运行时拒绝已知运行中、超时、取消和未完整读取的 Shell 结果作为有效实验；引用必须属于当前 Solver。语义上是否充分验证了算法仍由 Solver 判断，字段通过不等于独立技术验证。

撤销校准会递归撤销依赖记录及其结论。`basis_changed` 且 `control_failed` 时自动关联前一条同假设记录及其校准依赖；更广泛的失效来源通过 `revoked_sequences` 明确列出。环境失效由原生资源代次事件投影，保留原声明，并标明其已撤销。记忆检查点与观察器使用同一投影结果。

Chief 的环境重建理由要求说明验证假设、预期变化和退出条件；沿用现有 reason 和资源失效事件，不新增重置工具或调度层。这是提示层要求，不能保证模型每次都提供充分理由。

## HTTP 与观察器

HTTP 响应记录保留最终 `status_code`、`final_url`，新增 `initial_status_code`、`initial_url`、`follow_redirects` 和 `redirect_chain`。本地 302→500 场景验证初始与最终状态独立可见，原有会话和 Cookie 行为仍由现有引擎管理。

工具结果先按字段提取，再限制长度：保留执行状态、HTTP 链、输出、错误及证据引用，排除无关清理包络；嵌套数组只取有界样本并标记遗漏。超大单项也能进入窗口，不会阻止游标推进。Runner 保存 `observation_data` 时使用完整工具回执，避免主线的大结果投影先丢失关键字段。同一调用的参数以 call_context 关联；窗口内缺少调用参数时明确标 missing。

四组图谱接口、来源校验、最新窗口、撤销过滤、调用间隔、单并发、超时及无自动重试策略保持。增加对响应误读、任务状态冲突和失效校准继续使用的观察要求，仍允许空图。

性能报告区分输出 outcome、TENSION 条目数、实际收到的图谱版本数和 Solver 自报 assessment。`verified_correction_count` 保留 null，必须通过独立行为评估填写结论；TENSION 数、自报 corrected 和版本送达都不是收益证明。所有辅助物理请求继续使用现有 usage 账本。

## 验收证据与后续评估

证据目录：`.aion/verification/20260906-0305-round2/`。测试结果以 `pytest.log` 和 `final-targeted.log` 为准。

新增合成测试覆盖：完全不主动填报的真实 Runner、提醒送达失败和恢复、重复任务轮询、终态未读输出、隔离 ps 不影响后台状态、校准依赖撤销、环境变化、覆盖结果清除提醒、HTTP 完成去重、302→500 回执、包络尾部输出及超大嵌套结果。原观察器回归继续覆盖空图、非法来源、过期代次和迟到撤销。
