## 运行契约

### 提交与计量

`challenge_flag` 报告使用 `correct: bool | null`、`challenge_completed`、`awarded`、`duplicate`、`error` 和 `outcome`（`correct / incorrect / duplicate / unknown`），删除 `accepted`。题目完成不等于当前提交已确认正确；仅通过题目累计进度对账时，当前答案正确性和奖励仍为未知。既有不确定提交去重机制继续生效。

`aggregate_usage` 继续以物理请求 ID 去重，返回完整指标或 `null`，同时新增 `known_totals` 和按 `purposes` 分类的汇总。各范围保留 `calls_with_missing_usage`。性能分析中的提交计数使用 `correct_count`。工作台在计量不完整时展示未知完整消耗及已知输入／输出，不能将其解释为完整费用。

### 轻量实验复盘

独立入口 `solver_review` 的日常必填字段为 `hypothesis_id`、`covered_sequences`、`assessment`、`summary`、`next_test`。`solver_progress` 只更新状态与摘要，旧的嵌套复盘字段已删除。

`assessment=inconclusive` 可以直接记录未知、未校准、超时或未读结果。`no_new_information` 与 `new_information` 必须提供 `validation`，引用结论事件、对照证据，以及校准依据或有效校准记录。运行时校验引用归属、完成与读取事实及撤销关系，不证明任意脚本算法正确。

新增六个执行结果或紧急事件触发 Runner 提醒，附触发原因、待覆盖事件及最小示例；提醒不拦截工具，也不清除待复盘结果。只有成功的覆盖记录清除对应事件。连续无新增信息计数只来自有效的 `no_new_information` 记录。任务快照送达与自动触发分开计量。

复盘以 `solver_review_record` 保存并从事件恢复，支持撤销引用及观察器反馈。普通复盘不要求先选择 Skill；复用已有能力仍是提示建议。观察器反馈的 revision 与 assessment 成对提供，没有观察快照时均省略。

### 观察器

先验证全部条目、来源和冲突项，再按模型给定优先级每组保留前两项。诊断记录各组 `trimmed_entries`。即使条目位于裁剪范围外，非法来源、过长文本和来源不足的冲突项仍拒绝整次输出；不解包额外的 `map`。最终图谱继续受 1500 估算 token 上限约束。

观察器选择最近最多 80 个事件，并在 16000 字符预算内取连续后缀。未送入模型的旧事件记入 `coverage.skipped`，不会冒充已处理。只有实际送入模型的来源或旧图谱来源可以进入新图谱。纯记账窗口可以推进游标，但不更新图谱实际覆盖时间。

`map_coverage` 记录实际覆盖起止序号与截止时间；`coverage` 记录本批处理／失败／跳过情况；`backlog_events` 表示仍待处理的事件数。失败保留旧图谱实际覆盖时间。读取和保存图谱时移除引用已撤销来源的条目；复盘记录也进入观察输入。调用间隔、超时、单任务并发与无自动重试策略不变。
