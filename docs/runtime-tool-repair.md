# 运行事实、复盘与 HTTP 预检修复

本轮只实现与验证本地代码，保留工作区原有修改，未部署、未重启比赛。观察器继续关闭，记忆压缩策略不变。

## 实现契约

HTTP 的 `next_cursor` 仍是日志字节偏移。每页新增固定读取边界 `page_end_cursor` 和边界内的 `has_more`。默认结果列表必须在交互终态，且无筛选、从零连续覆盖全部默认记录，才标记已读。运行中读到当前末尾、跳页、筛选或只看最后一页均不能替代完整覆盖。

正文独立按 `interaction_id + request_id + body_sha256` 合并字节区间，不要求所有正文都读取；列表完整且交互终止即可退出普通待处理列表，正文覆盖留给结论校验。大结果被引用替换时延迟推进覆盖，实际读取引用后才确认送达。Runner 只做一次模型结果投影，避免正文分片又被截断而误记已读。状态投影和恢复使用事件，不解析 shell 文本。延迟读取旧的运行中页面只补覆盖，不能回退已经确认的终态。

Shell 的可信清理回执不会再因 owner 退出超过 0.2 秒而被覆盖为丢失：慢退出按记录的 PID 与创建时间有界回收，真正缺失回执仍失败。该问题由全量目录隔离测试暴露；原日志已证明越权读取被拒绝。

FastCGI 继续使用已有请求能力，错误统一经过 `tool_error`，原始错误、输出、完成状态和禁止自动重试信息穿过执行器与 Runner。未添加题目专用参数。

`solver_review` 独立记录复盘，`solver_progress` 不再接受嵌套 `review`。最小调用如下，序号必须取自当前 Solver 的实际事件：

```json
{"hypothesis_id":"local-check","covered_sequences":[42],"assessment":"inconclusive","summary":"结果尚未校准，结论未知","next_test":"读取结果并用已知夹具校验"}
```

`inconclusive` 不要求 validation 或先采用 Skill。`no_new_information`、`new_information` 必须包含 validation 的结论事件、对照证据及校准依据或有效校准记录引用。继续校验归属、执行完成、读取覆盖和撤销依赖，拒绝执行前错误作为校准结论；同批来源的子集或重排不重复累计负结果，不声称能证明任意脚本正确。观察器反馈字段必须成对提供，没有观察快照时省略。

新增六个执行结果或紧急事件触发提醒，附触发原因、待覆盖事件及最小示例。提醒不阻断工具，送达不清除待复盘结果；只有成功记录的覆盖关系才能清除。只有有效的无新增信息复盘累计负结果次数。

新配置 `selected_challenge_codes` 在创建 run 时去重、校验、持久化。在线脚本与部署启动命令均可重复传入 `--challenge-code a03 --challenge-code a05 --challenge-code a18`；省略为全目录。恢复沿用保存的范围，拒绝替换。指定集合平台确认全部完成、资源释放和子 Agent 收尾结束后，run 自然 completed。重复关闭完成题目保留完成状态，不取消正常收尾；主动停止未完成题目不计成功；外部中断不会因已有得分变成完成。提交确认完成后运行时结束 Solver 并保存带回执的收尾报告。全量回归还发现暂停与控制循环尾部等待写入的竞态；暂停状态现不会被迟到的等待覆盖，执行停止后再次确认暂停，资源释放失败仍保留占用容量。

`system_http_plan` 输入只包含 `tool_name`（request/probe）和 `arguments`。与实际执行共用参数模型、模板展开、文件及引用归属校验；返回总数、各 case 数量、前五个预览及截断标记。预检不发 HTTP、不写 Cookie 会话、不创建交互或任务、不计执行实验、不保存可执行计划或令牌。执行仍重新校验当前参数与文件。预览隐藏凭据，raw/base64 正文只展示类型和长度。

精确 `tool_search(name=...)` 返回经真实参数模型验证的示例，覆盖请求体、矩阵、正文分页和轻量复盘；下一轮直接调用返回的原生函数。旧通用 `{name, arguments}` 网关已删除，错误只给出独立的 `next_tool` 与 `next_arguments`。只有复杂矩阵或修正参数错误时建议预检，普通请求无需增加一轮。

HTTP 请求、Cookie 会话、矩阵、聚类分析和后台轮询均复用现有工具；同时修正 Solver 对已有 `system_http_analyze` 的权限遗漏。编码解码、签名脚本和独立 response diff 暂不新增：本轮没有证明独立通用需求，部分需求已被已有响应分析和本地处理覆盖。后续以重复出现的具体行为与错误率作为候选依据。
