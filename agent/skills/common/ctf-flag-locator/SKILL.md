# 可以去哪找 flag

适用于 CTF Web 已获得访问能力、需要决定下一步可以检查什么的阶段。
目标是形成并验证候选位置假设。下列载体只是可能性，不保证存在、可读或包含 flag。
具体路径、表名、端点、服务地址和凭据应来自当前题面或本次交互证据；
不要从其他题目、历史成功记录或评测环境惯例引入答案位置和专用利用链。

## 从已有结果开始

先检查已取得的完整响应、附件和命令输出，确认是否已有候选内容或位置线索。
复用已有证据句柄，不为重新看结果而重复请求。题面提供的格式或成功条件可帮助识别；
没有给出格式时，不默认必须符合某一种括号形式。名称包含 flag 或看起来像 flag
都只构成候选，示例、占位符和诱饵需要结合来源区分。

明确当前已验证的能力、身份、执行位置和回显限制。特别区分：

- 本地分析工具所在环境、目标 Web 进程、后台任务和内部服务可能不是同一文件系统。
- 任意文件读不一定能列目录；文件写不代表代码执行；管理员会话不代表操作系统权限。
- RCE 的子进程与服务主进程可能具有不同工作目录、环境变量和权限。

## 按能力选择候选载体

| 当前能力 | 可以检查什么 | 如何缩小范围 |
| --- | --- | --- |
| 登录态或管理员会话 | 可访问的页面、接口响应、下载与导出资源、业务完成结果 | 从当前页面链接、前端请求和源码确定入口，验证实际授权；业务目标可能通过正常动作返回候选内容 |
| 文件读取 | 应用配置、入口源码、启动配置、环境信息、挂载信息及其指向的文件 | 先确认读取语义和相对路径基准，再沿当前证据中的路径查找；源码可能说明内容由哪里加载 |
| 命令执行 | 应用目录、部署目录、环境变量、进程参数、挂载卷和运行时文件 | 先确认目标身份与工作目录，再做限定目录的名称/内容检索；由进程和配置确定其他位置 |
| 数据库读取 | 表结构、配置或业务记录、文本/二进制字段、指向外部存储的引用 | 先看 schema 和字段含义，再读相关记录；内容可能不以 flag 命名，也可能只保存路径或资源标识 |
| SSRF 或内部服务访问 | 已知服务的响应、状态/配置资源、应用使用的内部 API | 从本次配置、服务信息或错误中确定地址和协议，确认请求控制能力、认证和回显；不要默认可访问本机文件 |
| 文件写入或上传 | 已知可写资源的后续读取、渲染、下载或任务处理流程 | 查明谁会消费写入内容；若需要获得新的执行/读取能力，转交对应漏洞 skill，获得能力后重新定位 |

在 Linux 目标上，如果已有相应读取权限，进程信息、环境变量和挂载记录可以提供线索。
例如 `/proc/self/cmdline`、`/proc/self/environ`、`/proc/self/mountinfo` 是通用系统信息入口，
不是 flag 的预设位置；可用性与执行进程、系统配置有关。启动脚本和部署配置也可能说明
数据从文件、数据库、挂载卷或服务加载。按当前系统选择合适的信息源，不机械读取整份清单。

如果证据指向后台服务或本地 socket，可以检查协议、调用方式和可达性，判断它是否提供目标内容。
socket 的存在、服务以高权限运行或一个敏感文件不可读，都不能单独证明存在代读接口。
环境变量和配置中的密钥也可能只是访问材料，不应直接当作 flag。

## 给下一步排序

优先验证当前证据明确指向且现有能力能直接触达的候选，其次检查相邻的配置和元数据。
缺少线索时，可以提出少量常见目录、名称或字段假设，但必须标注为猜测；
不要把固定路径字典或无边界全盘内容扫描设为起手动作。
根据反馈逐步扩大范围：先已知应用资源，再相关部署/运行时位置，最后才考虑更广的检索。
目录范围、文件类型、输出大小与请求成本应适配已有能力；避免搜索伪文件系统时卡住或淹没回显。

每次选择能够回答一个具体问题的最小检查，说明：候选是什么、依据是什么、
当前能力能否检查、什么结果会支持或排除这个假设。可以同时比较少量独立候选，
无需把所有分支执行一遍。检查没有新增信息时，修正假设或补齐前提，再决定是否扩大范围。

## 使用轻量字典

目标路径、参数或文件名有题面、页面、JS、源码、技术栈或响应差异支持时，优先选择
`system_web_path_probe.packaged_wordlists` 中匹配的一类（例如
`web-paths-quick.txt`、`file-names-quick.txt` 或 `http-params-quick.txt`），或使用
现有参数探测能力做一次轻量检查。`wordlist_paths` 只用于 Agent workspace 中由当前证据
生成的文件，不能填写发布目录路径。自定义路径和页面派生字典默认最多 256 个候选；参数
候选最多 128 个，保持低并发、有限速率，并记录实际候选数和请求数。

取得文件读取、命令执行或明确 Linux 环境线索后，可以使用
在参数探测变量的 `file_path` 中使用 `packaged:linux-lfi.txt`。先用 `/etc/passwd`、`/proc/self/cmdline`、
`/proc/self/environ`、`/proc/mounts` 等已知资源校准读取通道，再按当前证据选择少量目标。
该文件是 Linux/LFI 检查候选，不代表这些路径一定存在或可读。

字典未命中只说明当前候选集合、入口或响应判定没有得到结果，保留原假设并转向能够区分
权限、路径基准、会话状态或执行环境的检查。页面内容构建的新字典放在后置阶段，来源限于
当前页面、JS、响应字段、链接、注释和错误信息；去重后限制为有限候选，并在下一步前重新说明依据。
口令候选只在存在明确认证入口、目标服务和授权依据时使用 `credentials-quick.txt`，
沿用工具的单服务、单用户名和低速率限制。

## 解释未命中并收敛

- 路径不存在、权限不足、读取通道不支持、编码问题、输出截断和执行环境错误需要分别判断。
  用已知可读资源校准路径与通道；不能从一个失败响应推出 flag 不在该系统。
- 环境变量没有线索，不排除文件或服务载体；数据库没有命中，也不意味着必须提权。
- 401/403 可能来自统一网关，404/500 也未必说明资源不存在。必要时与已知资源和不存在资源对照；
  会话与页面状态不一致时，检索 `web-ctf-flow`。
- 候选内容出现后，保留来源、读取方式和完整结果引用。停止无关枚举；
  按当前任务约定验证或由 Solver 提交，只有验证/提交接受才能报告成功。
  无验证渠道时明确标记为未验证候选。

简要记录：已验证能力及所在环境、候选载体及证据、最小检查、结果与局限、下一项不确定性。
原始凭据和候选值保留在证据中，普通进度摘要引用证据即可。
