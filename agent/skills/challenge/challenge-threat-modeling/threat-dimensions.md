# 威胁建模维度 · 类型路由与基础维度

> **上下文控制**：本文件是威胁建模的**路由层 + 公共基础维度**，刻意保持精简。四类题目的**专属深度维度**拆在各独立文件夹（`web/` `binary/` `ai/` `blockchain/`），一道题**只加载它对应的那一个文件夹**，避免多模块提示词互相冲突、挤占上下文。

## 一、类型路由（类型由平台确定，无需识别）

题目**类型**（`challenge_type`）由平台在分发时确定并随题目下发（取值：`web` / `binary` / `ai` / `blockchain`）。威胁建模时**直接按该类型加载且仅加载**对应文件夹：

| `challenge_type` | 建模维度 |
| --- | --- |
| `web` | [web/dimensions-web.md](web/dimensions-web.md) |
| `binary` | [binary/dimensions-binary.md](binary/dimensions-binary.md) |
| `ai` | [ai/dimensions-ai.md](ai/dimensions-ai.md) |
| `blockchain` | [blockchain/dimensions-blockchain.md](blockchain/dimensions-blockchain.md) |

> **执行 Agent 同路由**：挑战 Agent 按 `challenge_type` 分派给对应执行 Agent，发现能拿 flag 的漏洞后直接发布详细利用任务（见 SKILL.md「分派提示词」）。

**路由规则**：
- 类型明确 → 只加载对应文件夹，其余三个不进入上下文。
- 混合题（如 `web` + `blockchain`）→ 加载主类型文件夹 + 次要类型文件夹，主次分明。
- 类型缺失 / 无法判断 → 反馈补全，或先按 `web` 处理，据实际暴露面改判。

## 二、公共基础维度（所有类型通用，先铺这一层）

无论类型为何，先沿以下维度建立**第一层攻击面骨架**（记录字段见 [SKILL.md](SKILL.md)「威胁模型记录」）：

| 维度 | 自问 | 落点 |
| --- | --- | --- |
| **入口与暴露面** | 题目暴露哪些端口/服务/路径/功能/附件？ | 攻击面候选 |
| **资源/对象归属** | 对象 ID 是否有序可枚举？能否访问他人资源？ | IDOR、越权 |
| **输入面** | 输入从哪进？文件/流量/请求/命令行/上传/对话？ | 攻击面候选 |
| **数据流** | 数据从哪进、经哪些处理、到哪出？flag 在哪一步出现？ | 攻击链定位 |
| **输出通道/带外** | 是否有让目标外连的通道可读文件/打内网/外带 flag？ | SSRF、回连、外带 |

## 三、使用方式

1. 从平台下发取 `challenge_type`，只加载对应文件夹。
2. 先铺**公共基础维度**骨架，再沿**专属文件夹**的深度维度铺开。
3. 每个候选攻击面记一条威胁记录（按 SKILL.md 的字段）。
4. 排优先级收敛，形成可交付威胁模型。

> 建模纪律：**穷举再收敛**——先沿维度铺开，再按「难度 × 得分 × 可行性」排优先级，不一开始锁死单一方向；`name` 是最大线索，`hint` 是停滞时的方向修正锚点。
